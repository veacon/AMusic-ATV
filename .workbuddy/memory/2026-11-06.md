- 关键代码事实（后续改造直接复用）：
  - 音频 URL 唯一出口 `MusicRepository.kt:282 streamUrl()`，`repo.streamUrl(` 在 PlayerViewModel 出现 6 处。
  - DRM 三条分支：`PlayerViewModel.kt:2113 buildStandaloneSource` / `2209 buildDecryptedStandaloneSource` / 代理 `server/src/routes/stream.ts` + `stream_decrypt.py`。
  - 必须删除：`media/widevine/*`（含 `WvdBlob.kt` 内嵌 Widevine L3 凭证）、`AppleMusicDrmCallback`、`LiveRadioDrmCallback`、MV/电台模块、`EncryptedAudioStore`、`SystemAudioLoader`、`CatalogSongRecovery`。
  - 全仓库无 `isrc` 字段——Apple API 有 `attributes.isrc`，接进来可显著提升落雪侧匹配精度（低成本高收益）。
- 关键结论：LX/落雪自定义源协议只有 `musicUrl`（+local 的 lyric/pic），**不含搜索**；Apple 侧无平台曲目 ID → 必须自建「搜索 + 匹配」层，这是项目成败手。
- 法务：删掉 DRM 后最重的"规避技术措施"风险消失；剩 Apple ToS/商标 + 第三方音源侵权（分发即帮助侵权）+ GPL-3.0 必须开源。
- 推荐形态：服务端解析+中继（方案 A），TrackResolver 做成可插拔接口，未来可切 BYO 音源（本地/WebDAV/Navidrome）。

## P0 探针实测（同日下午，已完成）

用户决策：纯自用 / 无 PC / 直接用社区脚本 / 保留 Apple 品牌 / 5% 失败自动换源 / 要高音质+MP3 兜底 / 不保留个人库（抓 Apple 未登录通用数据）/ 先做 P0。

- 用户音源包：`D:\...\洛雪音源.zip` → 解压到 `F:/AI/am/aml/luoxue/音源/`（15 个 js）。
- 自建工具链在 `F:/AI/am/aml/probe/`：`lxhost.mjs`（LX 宿主模拟器，Node vm + lx.request/utils shim）、`search.mjs`（163/QQ/酷狗搜索+打分）、`verify.mjs`（魔数校验+码率反算）、`triage.mjs`/`idtest.mjs`/`e2e2.mjs`（三级实验）。
- 核心结论：
  - 裸测（只给歌名+歌手）：15 个脚本仅 1 个可用（K×H），且**只出 128k MP3**，请求 master 也静默降级。
  - 带平台 ID：7 个脚本出真 FLAC，最高 3534 kbps（wy master）。
  - 全链路 20 首：**19/20 命中（95%）、18/20 真 FLAC（90%）、中位 4567 kbps**；解析 p50 239ms / p90 3.3s / 最坏 40s。
  - 唯一 MISS = 繁简+艺人英文名（後來的我們 / Mayday）→ 需 ICU 繁简转换 + 艺人别名 + 时长兜底。
  - 直链 TTL 实测 ≈21 分钟（163 URL 内嵌时间戳）；FLAC 的 Content-Type 谎报 audio/mpeg，必须按扩展名/魔数设 mimeType。
- 架构定稿：端内 QuickJS 跑脚本 + Kotlin 自建搜索层 + 脚本级联 + 直链校验，无服务端。
- 报告：`F:/AI/am/aml/probe/P0-实测报告.md`；可行性文档已加"P0 实测更新"章节修正原判断。
